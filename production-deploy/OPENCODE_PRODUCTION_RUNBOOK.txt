CORE PRINCIPLE:

You do NOT need to install MongoDB, Redis, Node.js, pnpm, Go, Nginx, or
Certbot directly on the host OS. Only Docker + Docker Compose v2 are needed.

SECTION 1: VERIFIED 100% DOCKERIZED CONTAINER TOPOLOGY
--------------------------------------------------------------------------------
1. `oozox_mongo_prod` (`mongo:7.0`)
   - Network: `oozox_data_internal` (`internal: true` — completely isolated, zero
     public port mapping and zero internet egress).
   - Storage: Persistent Docker volumes `oozox_mongo_data` & `oozox_mongo_config`.
   - Least-Privilege Auth: `deploy/mongo/init-app-user.sh` provisions
     `MONGO_APP_USER` (`readWrite` on `oozox_prod_db` ONLY).
   - Field-Level Encryption: Sensitive fields (`Invoice.notes`,
     `Notification.message`) are encrypted at rest with AES-256-GCM
     (`ENC_GCM_V1:...`) using `DB_ENCRYPTION_KEY`. User passwords use `bcrypt(12)`.

2. `oozox_redis_prod` (`redis:7-alpine`)
   - Network: `oozox_data_internal` (`internal: true` — completely isolated).
   - Storage: Persistent Docker volume `oozox_redis_data` with AOF (`--appendonly yes`).
   - Auth & Limits: Protected by `--requirepass`, `512mb` maxmemory (`volatile-lru`).

3. `oozox_api_prod` (Built from `./backend/Dockerfile`)
   - Stack: Node.js 20 + Express + Mongoose + Zod + Helmet + Rate Limit (port 5000).
   - Networks: `oozox_data_internal` + `oozox_edge`.
   - Endpoints: `/api/health`, `/api/auth/*`, `/api/invoices/*`, `/api/notifications/*`.
   - Fails fast on startup if `MONGO_URI`, `JWT_SECRET` (32+ chars), or
     `DB_ENCRYPTION_KEY` (32+ chars) is missing/weak.

4. `oozox_signaling_prod` (Built from `./backend-signaling/Dockerfile`)
   - Stack: Go 1.22 + Gorilla WebSocket + Redis + HMAC-SHA1 TURN (port 8080).
   - Networks: `oozox_data_internal` + `oozox_edge`.
   - Endpoints: `/health`, `/ws` (WSS + JWT), `/match`, `/turn-credentials`, `/status/load`.
   - `POST /auth/token` is disabled in production (`APP_ENV=production`).

5. `oozox_web_prod` (Built from `./deploy/web/Dockerfile`)
   - Multi-stage Docker build: Stage 1 builds React 19 + Vite 7 SPA via pnpm;
     Stage 2 serves static assets on internal port 80 with `nginx:1.27-alpine`.
   - Network: `oozox_edge`.

6. `oozox_nginx_prod` (`nginx:1.27-alpine` + `./deploy/nginx/nginx.conf`)
   - Host Ports: `80` (ACME + HTTPS redirect), `443` (TLS 1.2/1.3).
   - Routes:
     * `oozox.com`, `www.oozox.com`, `admin.oozox.com` -> `http://web:80` (+ `/api/` -> `http://api:5000/api/`)
     * `api.oozox.com`                                -> `http://api:5000`
     * `signaling.oozox.com`                          -> `http://signaling:8080` (with WebSocket `/ws`)

7. `oozox_coturn_prod` (`coturn/coturn:4.6-alpine` + `./deploy/coturn/turnserver.conf`)
   - Network: `network_mode: host` (required for high-throughput RTP/SRTP UDP 49152-65535).
   - Ports: `3478/tcp+udp`, `5349/tcp` (TLS), `49152-65535/udp`.

8. `certbot` (`certbot/certbot:latest`, Compose profile: `certbot`)
   - Runs as an on-demand Docker container sharing `/etc/letsencrypt` and `/var/www/certbot`.

9. Android Client App (`app/` — built on CI or workstation)
   - Hardened with `android:allowBackup="false"`, hardware-backed `AndroidKeyStore`
     master DEK wrapping (`RoomLocalAES256Engine.kt`), and `PBKDF2WithHmacSHA256`
     (65,536 iterations) + `AES-256-GCM` (`HiddenAccountSecurityEngine.kt`).

SECTION 2: MINIMAL HOST PREREQUISITES, DNS & FIREWALL
--------------------------------------------------------------------------------
1. Server Minimum Specs:
   - Ubuntu 24.04 LTS or 22.04 LTS (x86_64)
   - 4 vCPU, 8 GB RAM (minimum 2 vCPU / 4 GB RAM), 60+ GB NVMe SSD
   - Static Public IPv4 (`SERVER_PUBLIC_IP`)

2. DNS A Records (Point BEFORE issuing SSL certificates):
   - oozox.com            -> <SERVER_PUBLIC_IP>
   - www.oozox.com        -> <SERVER_PUBLIC_IP>
   - admin.oozox.com      -> <SERVER_PUBLIC_IP>
   - api.oozox.com        -> <SERVER_PUBLIC_IP>
   - signaling.oozox.com  -> <SERVER_PUBLIC_IP>
   - turn.oozox.com       -> <SERVER_PUBLIC_IP> (MUST be DNS-Only / Proxy OFF!)

3. Minimal Host Setup (ONLY Docker + UFW + OpenSSL + jq — zero DB/runtime on host):
   sudo apt update && sudo apt upgrade -y
   sudo apt install -y curl git ufw openssl jq cryptsetup

   # Stop any pre-installed host web/db services if present on the VPS
   sudo systemctl disable --now nginx apache2 mongod redis-server 2>/dev/null || true

   sudo ufw default deny incoming
   sudo ufw default allow outgoing
   sudo ufw allow 22/tcp              # SSH
   sudo ufw allow 80/tcp              # HTTP + Let's Encrypt ACME
   sudo ufw allow 443/tcp             # HTTPS + WSS
   sudo ufw allow 3478/tcp            # Coturn STUN/TURN TCP
   sudo ufw allow 3478/udp            # Coturn STUN/TURN UDP
   sudo ufw allow 5349/tcp            # Coturn TURNS TLS
   sudo ufw allow 49152:65535/udp     # WebRTC Media Relay
   sudo ufw --force enable

   curl -fsSL https://get.docker.com | sudo sh
   sudo usermod -aG docker "$USER"
   newgrp docker
   docker --version && docker compose version

SECTION 3: HOST DISK ENCRYPTION FOR DOCKER VOLUMES (LUKS2) - RECOMMENDED
--------------------------------------------------------------------------------
Encrypt Docker's storage partition with LUKS2 (`dm-crypt`) so containerized
MongoDB & Redis volumes are encrypted at the OS block layer as well:

   # Example for a dedicated secondary disk /dev/sdb (DO NOT run on OS root disk):
   sudo cryptsetup luksFormat --type luks2 --cipher aes-xts-plain64 --key-size 512 /dev/sdb
   sudo cryptsetup open /dev/sdb oozox_encrypted_data
   sudo mkfs.ext4 /dev/mapper/oozox_encrypted_data
   sudo mkdir -p /mnt/oozox_data
   sudo mount /dev/mapper/oozox_encrypted_data /mnt/oozox_data

   echo '{"data-root": "/mnt/oozox_data/docker"}' | sudo tee /etc/docker/daemon.json
   sudo systemctl restart docker

2. Generate strong random secrets (NEVER leave any CHANGE_ME placeholder):
   export SERVER_PUBLIC_IP=$(curl -4 -fsS https://ifconfig.me)
   export MONGO_ROOT_PASS=$(openssl rand -hex 24)
   export MONGO_APP_PASS=$(openssl rand -hex 24)
   export DB_ENC_KEY=$(openssl rand -hex 32)
   export REDIS_PASS=$(openssl rand -hex 24)
   export JWT_KEY=$(openssl rand -hex 48)
   export COTURN_KEY=$(openssl rand -hex 32)
   export BACKUP_ENC_PASS=$(openssl rand -hex 32)

   cat > .env.production <<EOF
   SERVER_PUBLIC_IP=${SERVER_PUBLIC_IP}
   TURN_REALM=turn.oozox.com

   MONGO_ROOT_USER=oozox_root
   MONGO_ROOT_PASSWORD=${MONGO_ROOT_PASS}
   MONGO_APP_USER=oozox_app
   MONGO_APP_PASSWORD=${MONGO_APP_PASS}
   MONGO_DB_NAME=oozox_prod_db

   DB_ENCRYPTION_KEY=${DB_ENC_KEY}

   REDIS_PASSWORD=${REDIS_PASS}

   JWT_SECRET=${JWT_KEY}
   JWT_EXPIRES_IN=7d

   CLIENT_ORIGIN=https://oozox.com,https://www.oozox.com,https://admin.oozox.com
   ALLOWED_ORIGINS=https://oozox.com,https://www.oozox.com,https://admin.oozox.com
   API_RATE_LIMIT_MAX=500

   COTURN_SECRET=${COTURN_KEY}
   TURN_URLS=turn:turn.oozox.com:3478?transport=udp,turn:turn.oozox.com:3478?transport=tcp,turns:turn.oozox.com:5349?transport=tcp
   TURN_TTL=3600

   VITE_API_BASE_URL=https://api.oozox.com
   EOF

   chmod 600 .env.production
   echo "BACKUP_ENCRYPTION_PASSPHRASE=${BACKUP_ENC_PASS}" > /opt/oozox/.backup.key
   chmod 600 /opt/oozox/.backup.key

   grep -n "CHANGE_ME" .env.production && echo "ERROR: Replace placeholders!" || echo "ENV_CLEAN_OK"

   CRITICAL: Back up `DB_ENCRYPTION_KEY` and `/opt/oozox/.backup.key` offline.
   Without `DB_ENCRYPTION_KEY`, encrypted `Invoice.notes` and `Notification.message`
   fields cannot be decrypted.

SECTION 10: AES-256 ENCRYPTED BACKUPS, DOCKER SSL RENEWAL & UPDATES
--------------------------------------------------------------------------------
1. Create AES-256 Encrypted Daily MongoDB Backup Script (`/opt/oozox/backup_mongo.sh`):
   cat > /opt/oozox/backup_mongo.sh <<'EOF'
   #!/usr/bin/env bash
   set -euo pipefail
   source /opt/oozox/repo/.env.production
   source /opt/oozox/.backup.key
   BACKUP_DIR="/opt/oozox/backups"
   TS=$(date +"%Y%m%d_%H%M%S")
   mkdir -p "$BACKUP_DIR"

   OUT_FILE="$BACKUP_DIR/oozox_mongo_${TS}.archive.gz.enc"
   docker exec oozox_mongo_prod mongodump \
     --username="$MONGO_ROOT_USER" \
     --password="$MONGO_ROOT_PASSWORD" \
     --authenticationDatabase=admin \
     --db="${MONGO_DB_NAME:-oozox_prod_db}" \
     --archive --gzip \
   | openssl enc -aes-256-cbc -salt -pbkdf2 -iter 200000 \
     -pass env:BACKUP_ENCRYPTION_PASSPHRASE -out "$OUT_FILE"

   chmod 600 "$OUT_FILE"
   find "$BACKUP_DIR" -type f -name "*.archive.gz.enc" -mtime +30 -delete
   echo "Encrypted Backup OK: $OUT_FILE"
   EOF
   chmod 700 /opt/oozox/backup_mongo.sh

2. Cron Jobs (`crontab -e`) — Uses Dockerized Certbot + Dockerized Backup:
   0 3 * * * /opt/oozox/backup_mongo.sh >> /var/log/oozox_backup.log 2>&1
   0 4 * * 1 cd /opt/oozox/repo && docker compose -f docker-compose.prod.yml --env-file .env.production run --rm certbot renew --webroot -w /var/www/certbot && docker exec oozox_nginx_prod nginx -s reload >> /var/log/oozox_certbot.log 2>&1

3. Zero-Downtime Rolling Update inside Docker:
   cd /opt/oozox/repo
   git pull origin main
   docker compose -f docker-compose.prod.yml --env-file .env.production build api signaling web
   docker compose -f docker-compose.prod.yml --env-file .env.production up -d --no-deps api signaling web
